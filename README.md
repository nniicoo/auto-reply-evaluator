# 客服自动回复质量评估系统

## 一、项目概述

本项目实现了一套可运行的客服自动回复质量评估方案，将业务方的模糊需求转化为可量化的评估指标，对 20 条自动回复进行逐条评分，并输出评估报告。

## 二、评估指标定义

### 指标一：回复准确性（权重 40%）

| 分数 | 标准 |
|------|------|
| 5分 | 完全准确，精准回答用户问题 |
| 4分 | 基本准确，有小的不精确之处 |
| 3分 | 部分准确，存在遗漏或模糊表述 |
| 2分 | 准确性不足，存在明显错误或误导 |
| 1分 | 严重不准确，可能造成用户误解 |

**选择理由**：对应业务方"回复要准确，不能乱说"的要求。准确性是客服回复的基础，错误信息会直接损害用户体验和信任度，给予最高权重。

### 指标二：回复完整性（权重 35%）

| 分数 | 标准 |
|------|------|
| 5分 | 完整覆盖所有要点，信息充分 |
| 4分 | 覆盖主要要点，有少量遗漏 |
| 3分 | 覆盖部分要点，关键信息有遗漏 |
| 2分 | 严重不完整，大部分要点未覆盖 |
| 1分 | 几乎未回答用户问题 |

**选择理由**：对应业务方"回答要全面，不能漏掉用户的问题点"的要求。不完整的回复会导致用户反复咨询，增加人工客服负担。

### 指标三：语气得体性（权重 25%）

| 分数 | 标准 |
|------|------|
| 5分 | 专业友好，有温度，符合优质客服标准 |
| 4分 | 较为专业，语气尚可 |
| 3分 | 中规中矩，略显生硬 |
| 2分 | 语气冷淡或敷衍 |
| 1分 | 语气不当，可能引起用户不满 |

**选择理由**：对应业务方"语气要像真人客服，不能太机械"的要求。语气影响用户感受，但相比准确性和完整性，属于锦上添花，权重相对较低。

## 三、评估方法

### 技术方案：LLM-as-Judge

采用"LLM 作为评审员"的评估范式：

1. **构建评估 Prompt**：将用户问题、自动回复、评分标准组合成结构化提示词
2. **LLM 评分**：调用 LLM API 对每个维度打 1-5 分并给出理由
3. **加权汇总**：按预设权重计算加权综合分
4. **报告生成**：输出整体统计、分布分析、最差 Case

### 两种运行模式

- **Mock 模式**（默认）：使用预设评分，无需 API Key，便于演示和验证评估框架
- **LLM API 模式**：接入真实 LLM（如 OpenAI），评分更客观，设置 `USE_LLM_API=True`

### 评估流水线

```
数据加载 → 逐条评估 → 加权计算 → 报告生成
    ↓           ↓           ↓           ↓
auto_replies  LLM打分    权重*分数    统计分析
.json         (1-5分)    汇总得分    最差case
```

## 四、运行结果

### 整体得分

| 指标 | 均分 |
|------|------|
| 综合加权得分 | 3.53 / 5.00 |
| 准确性 | 3.95 / 5.00 |
| 完整性 | 3.15 / 5.00 |
| 语气得体性 | 3.40 / 5.00 |

### 质量等级分布

| 等级 | 数量 |
|------|------|
| 优秀 (≥4.5) | 3 条 |
| 良好 (3.5-4.5) | 7 条 |
| 一般 (2.5-3.5) | 7 条 |
| 较差 (<2.5) | 3 条 |

### 最差 3 条 Case

#### Case 1: ID=14（得分 1.00）

- **用户问题**：怎么注册会员？有什么好处？
- **自动回复**：您好。
- **问题**：回复只有"您好"，完全无效，零信息量
- **改进建议**：必须包含注册流程和会员权益说明

#### Case 2: ID=9（得分 1.65）

- **用户问题**：这个颜色还有货吗？
- **自动回复**：您好，请问您要哪个颜色呢？
- **问题**：未提供任何有效信息，反问式回复显得敷衍
- **改进建议**：应列出所有可选颜色及库存情况

#### Case 3: ID=12（得分 2.40）

- **用户问题**：我的优惠券用不了，显示已过期
- **自动回复**：您好，请检查优惠券的使用条件和有效期。如果有问题请联系客服。
- **问题**：回复过于简单，未分析可能原因
- **改进建议**：分析可能的原因并提供排查建议

## 五、局限性讨论

### 当前评估方法可能不准的情况

1. **复杂多轮对话**：当前评估基于单轮问答，无法评估上下文连贯性
2. **领域专业性**：LLM 可能缺乏特定行业知识（如医疗、金融），导致评分偏差
3. **文化语境**：中文客服的委婉表达、网络用语等，LLM 理解可能不准确
4. **主观性指标**：语气得体性具有主观性，不同评审可能给出不同分数
5. **边界情况**：需要特殊处理的 case（如投诉、退款），通用评估标准可能不够细化

### 改进方向

1. **引入人工抽检**：对低分和高分 Case 进行人工复核，校准评分标准
2. **多模型交叉验证**：使用多个 LLM 分别评分，取平均或投票
3. **构建评测集**：积累标注数据，计算评估一致性（Cohen's Kappa）
4. **细粒度指标**：针对特定场景（投诉处理、售后咨询）设计专项指标
5. **实时反馈闭环**：将用户满意度数据接入，验证评估与实际体验的相关性
